# 餐局访问控制任务清单

> 前置条件：`SPEC-meal-access.md` 与 `tasks/meal-access-plan.md` 已确认。

> 边界：本清单只落地数据库访问模型、RLS 与接入说明；不创建 Supabase 项目、不执行远程 SQL、不接入实时同步或微信登录。

## 1. 事件关系映射的测试先行

- [ ] 用固定 UUID 餐局夹具写失败测试，覆盖领域 `MealEvent` 到事件、成员、可用时间、偏好、候选、投票、决议和历史行的映射。
- [ ] 覆盖非法或缺失归属 ID 的拒绝路径，避免把本地模拟身份误写为云端身份。

验收：测试先失败，后续实现以行数据和归属 ID 可审计为准。

## 2. 实现纯映射层

- [ ] 新建独立的 `mealAccessSchema` 服务，仅负责领域对象与数据库行之间的转换，不读取环境变量、不发网络请求。
- [ ] 导出明确的行类型与映射函数，供下一阶段的云端事件仓储复用。

验收：第 1 步测试通过，现有本地餐局流程不受影响。

## 3. 编写不可变的数据库迁移

- [ ] 在 `supabase/migrations/` 增加带时间戳的 SQL 迁移，创建八张餐局关系表、必要索引、约束和更新时间触发器。
- [ ] 创建“创建者自动成为成员”的触发器，限制重复成员、重复时段、重复投票和不合法评分/状态。
- [ ] 迁移仅作为待执行工件；不在没有项目、没有用户授权的情况下连接或执行远程数据库。

验收：关系、约束和触发器与 `SPEC-meal-access.md` 一致。

## 4. 落地最小权限 RLS

- [ ] 为八张表启用 RLS，并提供固定搜索路径的成员/创建者判定函数。
- [ ] 只向 `authenticated` 授予所需表操作；成员只读共享数据且仅编辑自己的时段、偏好与投票，创建者管理餐局核心内容。
- [ ] 不授予 `anon` 表权限，不写浏览器端服务角色密钥。

验收：策略与规格中的权限矩阵逐项对应，未登录访问没有授权路径。

## 5. 补充项目接入与人工验证说明

- [ ] 新增 Supabase 设置指南：匿名登录开关、环境变量、迁移执行步骤及三位访客用户的 RLS 验证场景。
- [ ] 明确哪些步骤必须由你在真实 Supabase 项目中确认或执行。

验收：没有项目凭据时，任何开发者都能安全审阅工件；有项目时可按指南完成手工验证。

## 6. 验证、归档和本地提交

- [ ] 运行新增测试、完整测试、生产构建和 `git diff --check`。
- [ ] 精确暂存本任务文件，不包含现有未提交的 `vite-plugin-singlefile`、`HANDOFF.md`、`dist-single/` 或 `docs/onboarding-design/` 改动。
- [ ] 创建本地 Git 提交；远程推送另行征得确认。

验收：命令输出和提交内容可复现，工作区原有改动仍保持未暂存。
