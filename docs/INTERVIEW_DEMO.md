# Eato · 面试官体验版（独立演示）

## 一句话说明

Eato 面向朋友多人约饭时的时间协调、口味冲突、候选餐厅选择问题，将散落群聊的决策过程收敛到一个可解释、可确认的闭环。

**推荐体验入口：** 应用部署后的 /demo 路由（GitHub Pages 基路径是 /eato/demo）。
该路由无需注册，无需 Supabase 配置，所有成员、餐厅和价格都是**明确标注的演示数据**。

> 尚未验收部署前，不要把以上路径当作已验证可用的面试链接。正式交付前需实测无痕浏览器和手机端。

## 面试官独立体验（建议 90 秒）

1. 打开 /demo，阅读问题与场景：三位朋友约饭，每人的可用时间和口味不同。
2. 在「谁什么时候有空」切换小美 / 阿帅 / 阿豪，调整某个时段，观察方案是否从「可确认」变成「共同时间未齐」。
3. 在「想吃什么」修改某位成员的偏好，观察规则评分和排序变化。
4. 浏览三家虚构候选餐厅及其参考价格，观察时间/口味/预算分项得分和缺失信息警示。
5. 先点击「否决」，看方案被禁止确认；再改为「支持」，点击「确认这家」，查看最终结果。可点「重新体验」重复测试。

## 功能机制与可信边界

- 使用项目原有的 rankMealOptions() 对时间、菜系、预算、距离和历史信号加权评分；默认权重为 35% / 25% / 15% / 15% / 10%。
- 使用原有 castVote() 与 confirmDecision()，保证没有全员共同时间或存在成员否决时不能确认。
- 候选名字和参考价纯属虚构；没有使用 AI 大模型或真实优惠采集接口。
- **此演示版不声称实现跨设备实时协作。** 真正协作需要另行验收 Supabase 身份、数据库权限、邀请和同步。
- 数据保存在页面运行时状态，刷新后恢复样例，且不会上传服务器；不收集个人信息。

## MVP 取舍（面试可讲）

优先验证「多人决策能否完整闭环」，将复杂数据接入放到次阶段。

| 能力 | 面试演示版 | 正式产品方向 |
| --- | --- | --- |
| 体验门槛 | 免登录、打开即操作 | 云端访客/真实协作 |
| 时间协调 | 多成员模拟数据、交互调整 | 多设备填写和同步 |
| 口味/预算 | 结构化偏好、可解释推荐 | 更多限制和个性化 |
| 比价 | 仅显示清楚标注的参考价 | 接入授权的价格来源及标记更新时间 |
| 结果确认 | 投票否决+共同时间约束 | 成员确认、分享、饭后记录 |

## 正式交付前的验收清单

- [ ] GitHub CI：npm test 与 npm run build 通过。
- [ ] 用无痕窗口访问线上 /demo，不登录不依赖第三方密钥，能完成五步演示。
- [ ] 手机宽度（375px）无明显遮挡，核心按钮可操作。
- [ ] 禁止虚构优惠被误认为实时价格，不能声称 AI/真实同步已实现。
- [ ] 主入口、原工作台和已部署的生产分支不受改动。
- [ ] 记录 3 秒加载/异常降级的真实测试证据；**未测试前简历不写已验证**。
- [ ] 补充公开的产品需求取舍说明、原型链接和用户测试记录，以支持简历内容。

## 面试展示重点

用问题 → 取舍 → 原型 → 技术实现 → 验证与局限的故事组织作品集，而不是只展示技术栈。不要把演示数据、规则评分或预期效果说成线上真实运营指标。
